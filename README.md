# 批量文件整理器

给一个目录，扫一遍，用内容哈希找出重复文件；**默认只预览不动手**，加 `--apply` 才真的把多余的副本移进 `_dup/` 隔离区。

一个练习项目，目标是搞清「按大小预筛 + 哈希判重 + dry-run + 日志」这套东西怎么落地。

## 功能

- 递归扫描目录，统计文件数、目录数、总大小，按扩展名分组
- 按 MD5 哈希判重：内容相同的文件归为一组
- **先按文件大小分组，只对大小相同的文件算哈希**（大小不同一定不同，省掉绝大部分读盘）
- 默认 **dry-run**：只打印「将 A 移到 B」，不碰磁盘
- `--apply` 才执行，且动作是**移动**不是删除
- 每次操作写日志，失败只记录、不中断
- 输出 `report.csv`：原路径、大小、哈希、重复组编号、建议动作

## 环境

- Python **3.12+**（用到 f-string 内嵌同名引号）
- 只用标准库，无第三方依赖

## 用法

```bash
# 预览：只打印计划，不改动任何文件
python organize.py D:\data

# 真的执行：把重复副本移进 D:\data\_dup\
python organize.py D:\data --apply

# 查看帮助
python organize.py --help
```

> 建议第一次先在一份**副本目录**上跑，别拿真实数据开刀。

## 输出

| 输出 | 位置 | 说明 |
|---|---|---|
| 扫描报告 | 终端 | 按后缀分组的数量、大小，以及总文件数、总大小 |
| 移动计划 | 终端 | 每一行「将 源 → 目标」，末尾给出总数 |
| CSV 报表 | 当前工作目录 `report.csv` | UTF-8-SIG 编码，Excel 直接打开不乱码 |
| 日志 | `logs/organize.log` | 时间、级别、每次移动的源与目标 |
| 隔离区 | `<目标目录>\_dup\` | 保持原来的子目录结构 |

CSV 示例：

```
重复组,原路径,大小(字节),哈希,建议动作
1,D:\data\照片\A.jpg,3145728,960e1c18ab...,保留
1,D:\data\备份\A.jpg,3145728,960e1c18ab...,归档
```

## 工作原理

```
遍历目录
  └─ 按「扩展名」分组
       └─ 组内按「文件大小」分桶          ← 大小唯一 = 不可能重复，直接跳过
            └─ 桶内 ≥2 个文件才算 MD5      ← 只有这些才真正读盘
                 └─ 按 MD5 归组：≥2 个 = 重复文件
```

为什么先比大小：读元数据几乎免费，读全文才贵。真实目录里大小恰好相同的文件是少数，这一步通常能省掉大部分哈希计算。

为什么哈希能代替两两比较：哈希是内容的一元「代表元」，`f(A) == f(B)` 即可判定相同。n 个文件的比较次数从 `n²/2` 降到 `n`，每次比较的代价从「读完整个文件」降到「比较 32 字节的字符串」。

## 安全设计

- **默认不动手**：不带 `--apply` 时零副作用，可反复运行
- **只移动、不删除**：所有被处理的文件都在 `_dup\` 里，随时能搬回去
- **不覆盖**：目标已存在时跳过并记 warning
- **失败不中断**：单个文件被占用/无权限时只记日志，继续处理其他文件
- **`_dup` 被排除在扫描之外**：避免第二次运行把隔离区里的文件再判一次重复，造成套娃
- **幂等**：同一命令跑第二次，第二次不会动任何文件

## 已知限制

- **保留规则比较简单**：同一组里按路径字符串排序取第一个，不是「保留最早的」或「保留最完整的一份」
- **跨盘移动非原子**：`shutil.move` 跨分区是「复制 + 删除」，中途失败可能留下半截文件
- **`rules.json` 还没接入**：目前只输出报表，尚未按扩展名/日期自动归档
- **硬链接会被当成重复**：同一份数据链接两次，删掉一个并不省空间
- **符号链接处理不完善**：扫描阶段未显式过滤
- 空文件全部同哈希（都是 `d41d8cd9...`），会被归为一组

## 开发记录

在 `C:\zzy的文件`（9877 个文件，共 423.97 MB）上跑了一次只读扫描：

- 识别出 **520 个重复副本**，约占全部文件的 5.3%
- 预计可回收 **1.10 MB**
- 未执行 `--apply`，没有任何文件被移动

一个观察：重复文件平均只有 2.2 KB，说明这个目录里的重复集中在 `.pyc`、配置、小 `.json` 这类小文件上。
清理收益几乎为零——但这也正好说明"判重"和"值得清理"是两件事：**先看清有多少，再决定动不动手**。
